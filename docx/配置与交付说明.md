# 配置与交付说明

## 配置从哪里读取

- 运行用户EXE：读取用户EXE所在文件夹的 `config.toml`，再叠加同级 `config.local.toml`。
- 运行调试EXE：读取调试EXE自己文件夹的两份配置，与用户包相互独立。
- 从源码运行：读取 `master` 文件夹的两份配置；改这里不会改变已打包EXE旁的文件。
- 选择命名机器后，`profiles/machines/<名称>.toml` 继续覆盖上述配置；选择自定义设定时，`profiles/custom/<名称>.toml` 最后叠加。
- `profiles/selection.toml` 只保存选中的配置名称，不保存标定本身。

因此，改模板不一定立即生效：local和命名配置中的同名键优先级更高。当前界面也会缓存本次选定的机器配置。

## 为什么两份config看起来都很杂

`config.toml` 是默认模板。`config.local.toml` 目前实际保存合并配置的完整快照，不是只保存改动过的键：向导写出的local里可能同时有默认值、用户输入和自动计算的值。命名机器配置也可保存除custom以外的完整快照，包括作业参数和对刀点。不能仅凭文件名或某字段出现在local中，就判断它来自用户输入。

本次先说明现状，不改变这些文件的合并优先级，不批量清除用户设置。

## 字段分类

| 分组与字段 | 来源与用途 | 交付到另一台电脑/工件时 |
| --- | --- | --- |
| servo.adapter | 接口页选择的EtherCAT网卡标识，绑定电脑网卡 | 必须重新选择，不携带本机网卡标识 |
| cnc3d.port、head.port | 接口页选择的COM号，绑定电脑及USB设备枚举 | 必须重新选择 |
| cnc3d.baud、head.baud | 模板提供的串口协议参数，通常115200 | 同型号控制板可保留默认值 |
| servo.lead_mm、counts_per_rev | 已标定的电机与变距机构参数；不是操作者每次输入 | 绑定硬件，同一套机器可沿用；换机构需重新标定 |
| servo.vel_mm_s、cnc3d.feed、cycle.valve_delay_ms | 模板中的运动/阀延时参数；目前用户任务页不逐项询问 | 随经确认的同款机器默认值交付 |
| head.travel_mm | 标称机械行程，默认50；不代表软件允许运动范围 | 同型号可保留；不能据此证明实际机械余量 |
| head.firmware_verified、datum_confirmed | 准备流程写出的确认状态 | 不移植已经确认的状态；新用户重新准备/对零 |
| head.standby_mm、work_min_mm、work_max_mm、cut_safe_mm | 准备流程生成的对刀待机位、软件窗口与剪丝位 | 用户版通常−15、±30、0；不能替代现场对机械余量的确认 |
| head.insertion_mm | 旧配置或向导留下的派生值 | 自动实机忽略此键，实际目标重新按待机位−深度/cos计算 |
| cnc3d.scan_z_mm | 准备流程写入的CNC坐标；调试版用作独立安全Z，用户版兼容保留 | 绑定本次坐标基准，不作为通用标定迁移 |
| cycle.cut_clearance_mm | 剪丝额外上抬距离；用户版固定15，旧调试流程允许输入 | 同流程可沿用默认值，新对刀仍重新确认 |
| cycle.wire_threading_enabled | 模板/人工编辑控制套丝；缺失时默认为true | 同工艺可用默认值 |
| cycle.upper_release_after_retract | 兼容旧0抬升流程的字段；正抬升流程仍等待剪丝确认 | 不据此判断当前是否立即松上阀 |
| job.angle_deg、count、depth_mm | 用户任务页输入，保存为下次默认值 | 可以保留通用默认值；不代表新工件已确认参数 |
| regions.gap_mm | 用户版任务页输入的沿管空白距离，保存在local及当前命名机器配置；一轮及各排不重复询问 | 任务参数，可作为下次默认值；新用户首次自行输入，没有暗设默认间距 |
| saved_touch_off整段 | 选择保存后，程序记录CNC XYZ、架角、接口/标定指纹与滑台位置 | 绑定工件、针组及坐标基准；清洁交付不携带 |
| custom.needle_pitch_mm、travel_mm、x_mm、y_mm、z_mm | 自定义输入；保存自定义设定后用于下次填表 | 不恢复气阀或使能状态；XYZ目标仍可能绑定旧坐标，清洁交付不携带 |
| cnc3d.x_max、y_max、z_max | 历史残余键 | 上位机已忽略，CNC下位机负责限位 |

上位机写入的确认布尔值和位置回读不是独立机械测量；不能用保存文件代替每次开机人工归零确认。

## 最小用户交付内容

把完整运行目录交给用户，至少包含：

```text
ZpinControl/
  ZpinControlUI.exe
  _internal/              # 全部运行库，整个目录保留
  config.toml             # 使用源码中的干净模板
  使用说明.md
```

可另附Q&A、配置说明及固件源码；调试工具按需要单独交付。用户不需要Python/conda或项目源码。使用EtherCAT伺服时，首次在用户电脑安装Npcap。

首次交付不带本机的 `config.local.toml`、`profiles`、`runs`。程序在用户完成接口选择和准备后自动生成本机配置、命名档案及实验记录。不能只删local却留下旧profiles，因为命名配置仍可能把旧串口、网卡和对刀点覆盖回来。

若交付的是同一套物理机器，可以将经过确认的硬件标定数值整理到干净模板中；不要一并带走旧电脑端口、保存对刀点和已确认状态。

## 本机升级与首次交付不同

当前 `packaging/build.ps1` 为本机升级保留config.toml、config.local.toml、profiles和runs；因此现有dist目录包含实验环境资料，不宜直接原样交给新用户。制作首次交付副本时，以干净模板替换复制过去的config.toml，并在副本中排除上述本机文件。原工作目录和记录不删除。

本轮另外提供 `dist/ZpinControlDelivery` 清洁交付目录，只包含用户EXE、完整运行库、干净模板和用户文档，没有复制本机配置、命名档案或实验结果。首次交付优先使用该目录；本机升级仍使用 `dist/ZpinControl`。
