> 当前模型（2026-10-08）：预设固定20 mm强化区、10 mm针距、仅最右两针，选7/10/15根；角度仅0°、15°、30°。实机与自定义先共用机器配置和接口选择；伺服不可用只报错提示，未自动调整针距时须人工核对。自定义按动作连接组件，气阀只需GX28通信，不受CNC、伺服或滑台运动参数错误阻挡。

# Z-pin 五针植入控制 —— 交付包说明

植入深度沿垂直管面量，只要求有限且大于0，没有固定工艺上限。滑台实际行程为 `深度/cosθ`，仍受工作窗口限制；新版对刀位−10 mm、固件下限−15 mm时可再下行5 mm，0°深度5 mm可达，30°深度5 mm需下行约5.774 mm，会在连接设备前报告越界。剪丝距离与植入深度分别设置。

剪丝流程（2026-10-12）：零点确认后，先确保针尖离开工件、GX28下方有10 mm余量；允许后程序将滑台下移到−10 mm，为上抬预留空间，再手动调整CNC完成对刀。对刀后弹窗输入GX28上升距离，默认10 mm，可在0–10 mm内调整。程序上升并回读、记录安全位置：上升10 mm到0，上升3 mm到−7。旧5 mm准备配置重新对刀时采用新默认10 mm；新版已保存的自选距离继续沿用。CNC排间Z安全高度另行确认。

开始植入先下降到GX28对刀待机位，再向下走本次行程。每次退针后上升到剪丝安全位置，上气阀 B 一直夹紧，滑台电机保持使能。剪丝完成、双手离开后点击“继续”或按回车，B 阀排气，滑台下降回对刀待机位，才进入下一落点。最后一次也要确认剪丝，之后 CNC 才回排头。实机和自定义共用这些保存的机器参数。

自定义单次植入完成上抬后会停住，点击“剪丝完成，松上阀并恢复待机”才下降；等待时不能再次植入或重新设零。其它组件故障不影响独立气阀操作。距离设为0保留旧的立即释放上阀流程。

**使用新流程前需要烧录新版滑台固件。** 源码随包提供于 `firmware/insert_head/insert_head.ino`，工作窗口扩大为−15～+15 mm，协议仍为2，GPIO12/EN接线和防复位串口行为保持原样。这是相对人工零位的软件限位，并非物理限位开关。上位机在移动前核对固件窗口；旧固件会提前提示烧录，独立气阀仍可操作。烧录后先通过实机向导重新确认零位、准备、对刀和记录安全位置，旧配置不会自动变为已确认的新坐标。自定义单次植入按记录的对刀待机位定位工件，再运行。

这个文件夹是 PyInstaller 的构建输入。构建产物在 `dist\ZpinControl\`，那个文件夹
整个拷走就能用，目标机器上**不需要**装 Python、conda 或本仓库的源码。

产物里有**两个入口，一份业务**，挑一个用：

| 入口 | 形态 | 给谁用 |
|---|---|---|
| `ZpinControlUI.exe` | 窗口，双击即用 | 现场操作员 |
| `ZpinControl.exe`    | 控制台，终端菜单 | 脚本化调用、排查问题 |

两者读同一份 `config.toml`，跑的是同一套业务逻辑（实机运行、仿真、自检、配置档案、
完全自定义五条路径完全一致），区别只在"说话的对象"是对话框还是终端。安全路径
——急停、零点确认、连接前预检——两边一模一样。

## 构建

```powershell
powershell -File packaging\build.ps1
```

换 Python 解释器：

```powershell
powershell -File packaging\build.ps1 -Python C:\Python313\python.exe
```

默认执行策略下就能跑，不需要动 `-ExecutionPolicy`。只有当本机策略确实禁止运行
脚本（报 `无法加载文件……因为在此系统上禁止运行脚本`）时，才需要你自己决定是否
放行；不要在没看懂那条策略是干什么的情况下随手加 `Bypass`。

打包前请关闭正在运行的 Z-pin 程序。脚本先在独立目录构建，检查解释器、标准库与界面运行文件齐全后，才替换交付目录；构建失败不会清空原包。

替换时保留已有的 `config.toml`、`config.local.toml`、`profiles` 和 `runs`，没有配置才使用模板，并复制本文件为 `使用说明.md`。上一份目录保留在 `build/previous-delivery-*`，便于恢复。

验收（改完代码或换机器后都该跑一遍）：

```
cd dist\ZpinControl
.\ZpinControl.exe --smoke-test
```

期望输出 `已完成：12 个落点，共 3 排（每排 4 个）` 和 `阀门已关闭`，退出码 0。
这条命令不读配置、不开任何设备。

窗口版另有一条验收：双击 `ZpinControlUI.exe`，应当**直接出窗口、背后没有黑色
控制台**，点「自检」后日志面板里出现同样的 12 个落点。两条都要过——它们共用一个
`_internal\`，控制台版能跑不证明窗口版能跑（窗口版的 `sys.stdout` 是 `None`，
走的是一条单独的初始化路径）。

## 产物结构

```
dist\ZpinControl\
  ZpinControlUI.exe   ← 图形界面入口，双击即用（master/gui_main.py）
  ZpinControl.exe     ← 控制台入口，和源码 CLI 是同一个 master/master.py
  config.toml         ← 外部可编辑配置，装完必须改
  config.local.toml   ← 向导生成，存本机串口/网卡；首次运行前不存在
  runs\               ← 每次实机运行的 CSV 和 JSON 摘要；首次运行后出现
  _internal\          ← PyInstaller 的运行时载荷，两个 exe 共用，别动
  使用说明.md          ← 本文件
```

两个 exe 共用同一份 `_internal\`，所以装两个不会让体积翻倍。

`config.toml` 是**模板**，里面 `[job]` 段是注释掉的，`[servo] adapter` 和两个
`port` 是空的 —— 这是故意的：`--live` 在补齐实测值和工件零点之前会在打开硬件
**之前**就拒绝运行。

## 目标机器上要装什么

只有一个外部依赖：

- **Npcap** —— EtherCAT 走网卡抓包，pysoem 依赖它。从 <https://npcap.com/#download>
  下载安装。安装时勾选 "WinPcap API-compatible Mode"。

  本包**不分发** Npcap 安装程序：它的免费授权禁止再分发。请到官网自取。

pyserial 已经打进包里了，CH340 串口驱动（GX28 滑台和 CNC 三维模组用）是 Windows
自带或随设备附带的，本包也不含。

## 怎么用

### 首次配置

1. 使用伺服 EtherCAT 控制时先装 Npcap；仅控制气阀、滑台或 CNC 可跳过伺服接口。
2. 双击 `ZpinControlUI.exe`（或用终端跑 `ZpinControl.exe`），先选「接口与机器配置」。
   选择命名的机器配置或当前本机配置，逐项确认网卡和串口；未接的设备可跳过。
   选择会保存到 `config.local.toml`，再进入「实机运行」或「完全自定义」。直接进入任一分支时，也会先走这一步。
3. 之后每次开机，向导仍会让你确认一遍待机位置和零点 —— 断电重启后滑台和伺服都
   把当前点当作零位，那不代表机械零位。

### 图形界面

双击 `ZpinControlUI.exe`。窗口就是终端菜单的等价物，按钮与菜单项一一对应：

```
接口与机器配置 │ 实机运行 │ 仿真 │ 自检 │ 配置档案 │ 预设任务 │ 完全自定义
```

中间是日志面板，`print()`、向导提问、设备回显按发生顺序混在同一条流里，和终端里
的观感一致。红色行是警告（`  ! ` 开头），灰色行是设备回显。勾上「调试输出」后
设备每一行回话都会出现在面板里，与 `--debug` 是同一个开关。

底部三个按钮**只在运行期间可用**：

| 按钮 | 作用 | 对应终端里的 |
|---|---|---|
| 继续 | 放行一次操作员确认 | 按回车 |
| 排间收工 | 本排做完就正常收工，不再进下一排 | 输入 `D` |
| 急停 | 滑台急停、CNC 保持、伺服卸使能 | 输入 `!` |

急停走的是和终端**完全相同**的安全路径。点下去之后日志面板会打出"已紧急停止"，
这次运行以退出码 1 结束。关闭窗口时若正在运行，会先问一句，确认后同样先请求急停，
保持窗口响应，等停机和关阀收尾完成后再退出；不会到 5 秒后强制退出。

实机运行、配置档案、完全自定义三块的对话框与终端向导共用**同一份校验规则**，
包括报错文案；在输入框里敲 `Q`、`QUIT` 或 `取消` 与在终端里一样是中止。

### 菜单

在终端里不带参数运行 `ZpinControl.exe` 时进菜单：

```
  [1] 实机运行（会连接并可能移动机构）
  [2] 仿真（不接硬件）
  [3] 自检（参考作业 θ=+15° / 强化区 20 / 点距 2 / 3 排）
  [4] 调试输出：关
  [5] 配置档案（机器：未选择；作业：未选择）
  [6] 完全自定义
  [7] 预设任务（实机 / 仿真）
  [8] 接口与机器配置（实机 / 自定义共用）
  [0] 退出
```

全程用编号选择，只有在必须读数值（作业尺寸、点动距离）时才要求输入。
自定义中各组件按需连接；某一路配置或连接失败只影响该路动作。气阀只要求 GX28 串口可用；滑台移动与单次注入仍需确认零位及工作窗口。实机植入仍需 CNC 和滑台，伺服未连接、未设零或调距失败时显示警告，按当前机械针距继续。
`[4]` 是开关，改完回到菜单，不退出。`[5]` 改完当前档案后，菜单上的机器/作业名会
跟着更新。

### 调试输出

菜单里把 `[4]` 打开，或者命令行加 `--debug`：

```
ZpinControl.exe --live --confirm-datum --datum-x 0 --datum-z -5 --debug
```

`--datum-x` / `--datum-z` 是对刀点，**每次装夹都要重新量**，上面的数值只是占位。
非交互路径必须显式给出，少一个就会在连接设备之前报错退出——不带 `--confirm-datum`
走向导时不用填，向导会让你对刀两次把坐标读回去。

自动植入保持本次对刀时的 Y 坐标，整排和换排回排头均不移动到 Y=0。向导确认对刀点后，抬刀只调整 Z；若 Y 被改动，会提示重新对刀。命令行直接实机运行时沿用开始作业时的当前 Y。

打开后，设备自己说的每一行都原样打到终端，出错时**固件原话先出现，主控的转述
随后**：

```
[GX28] > -5.000
[GX28] < 移动到 -5.00 mm (16000 步)...
[GX28] < 到达目标
[CNC ] > G1 X10.000 Y20.000 Z0.000 F1500
[CNC ] < ok
[伺服] > 绝对定位 +0.000 mm
[伺服] < 状态字=0x0237 到位
```

CNC 每次移动都会每 0.1 秒发一次 `?` 查询状态，一秒 10 行一模一样的回话。那些是心
跳不是设备主动说的话，所以只在**状态变化**时打一次；`ok`、`error:N`、`ALARM:N`
一律原样打印。

关闭调试（默认）**不等于少看东西**：设备报的错一个字不少地传上去，只是不再回显
正常回话。

### 命令行的三种模式

菜单不是唯一入口，脚本化调用继续走参数：

```
ZpinControl.exe --smoke-test                          # 参考作业全流程，不接硬件
ZpinControl.exe --simulate --angle 30 --count 10 --depth 3   # 指定作业仿真
ZpinControl.exe --live --confirm-datum --datum-x 0 --datum-z -5 --debug    # 实机
```

`--smoke-test` / `--simulate` / `--live` 三者互斥。在**非终端**环境（管道、重定向、
计划任务）里不带模式参数运行会直接报用法错误，不会挂在那里等输入。

## 重新打包时要留意

- `packaging\ZpinControl.spec` 里的 `pathex` 不能删：`sv630n_pc` 和 `cnc_grbl` 是
  **运行期**才 `sys.path.insert` 进去的惰性导入，PyInstaller 在构建期看不到那两条
  路径，删了就会在实机连伺服/CNC 时才炸 ImportError。
- 控制台版的 `console=True` 不能改。`main()` 用 `sys.stdin.isatty()` 决定要不要给
  菜单，无控制台窗口时 `sys.stdin` 是 `None`。
- **`tkinter` 不能放回 `excludes`**：窗口版要用它。它在共用的 `_internal\` 里只占
  一份（约 3~5 MB），控制台版带着不用也无妨。真正排掉的是 `unittest` / `pydoc` /
  `doctest` / `pdb` 和科学栈；如果以后有模块真的要用，从 `excludes` 里删掉再加回去。
- **`Analysis` 收两个入口，但每个 `EXE` 只能拿一个**。spec 里那个 `scripts_for()`
  不是装饰：`analysis.scripts` 里是「runtime hooks + 两个程序脚本」，整个传给一个
  `EXE` 会让它把**两个入口都跑一遍**（实测：窗口版会先在后台跑一次终端主流程）。
  加第三个入口时，往 `_PROGRAM_SCRIPTS` 里加一行即可。
- 两个 `EXE` 必须进同一个 `COLLECT`，否则体积翻倍。
