# Z-pin 五针金属丝植入机控制系统

本项目用于科研实验中的碳纤维管金属丝植入。两轴横向扫描与工作高度由改装的 TwoTrees TTC450 Pro 三维模组执行；五针工位间距由 SV630N EtherCAT 伺服变距模组执行；GX28/2830 滑台和上下两个气阀完成夹丝、下针、换夹、退针。历史的 45° 并联机构放在 `firmware/legacy/`，不参与现流程。

`v0.1` Git 标签保存了目录整理后的原始基线。当前 `develop/v0.2` 分支修复与验证总控，详细顺序见 [实施计划](docs/superpowers/plans/2026-09-24-zpin-control-to-exe.md)，逐步证据见 [开发日志](DEVELOPMENT_LOG.md)。

## 已实现的离线流程

**一次作业 = 一排。** 管子在夹具上是被架斜的，**针始终竖直**；±15°、±30° 这些角度是靠把管子架到对应角度实现的，不是靠偏转针。用户提供架角 θ、一排的强化区长度、点间距和植入深度。排程器从五针的 `10–20 mm` 标定针距里选一个最接近 12 mm 的整数倍针距（必须是点距的整数倍）。参考作业为 θ=+15°、排长 20 mm、点距 2 mm、深度 2 mm：每排 10 个植入点、6 次五针动作，走完一排后滑台抬到安全高度、回到排头，等操作员剪丝并把管子转过一个周向位置，再跑一模一样的一排。**机器没有回转轴**，转了多少度程序既不校验也不提示。

强化区长度和点距**不要求整除**：排点数取 `floor(强化区/点距)`，末端不足一个点距的那一小段不扎针，向导会把实际覆盖长度和末端余量打出来。样件规划里三个密度都是 20 mm 强化区，其中 `2.75 mm`（7 个点、覆盖 19.25 mm）和 `1.30 mm`（15 个点、覆盖 19.5 mm）本来就除不尽，硬要求整数倍会让这两个密度根本进不去。只有强化区短于一个点距（放不下任何一个点）才拒绝。

θ 是**带符号**的：正值表示管面朝 +x 上升。针尖连线与管面平行，所以**排内 Z 必须跟着 X 走**：`z(x) = z0 + (x − x0)·tanθ`，`(x0, z0)` 是对刀点。排内 Z 不动的话，前置的针会一路扎进管壁——仿真台会独立复算这条剖面，对不上就记账并让自检以非零码退出。正负号是真实的机器差别：`+15°` 和 `−15°` 的针长等差步长反号（`d = p·tanθ`），必须用两套不同的针组。

植入深度沿**垂直管面**方向量，滑台竖直行程 = `depth/cosθ`，与 θ 的符号无关。所以下行目标由深度推导，配置里不再手填（`[head].insertion_mm` 写了也会被忽略）。

每一落点的顺序为：下阀 A 夹丝 → GX28 下行 → 关闭 A → 上阀 B 夹丝 → GX28 上行 → 关闭 B。此处保留此前在设备上验证过的“先下、后上”方向。滑台下行对应软件坐标减小。滑台实际下行距离与有效工作区间必须在实机上测定。

所有模式使用 `master/planner.py` 和 `master/coordinator.py`。模拟器替换设备接口，不重写排程或动作时序。故障与停止会阻止后续落点，并尝试停机和关闭两个阀。

## 源码运行与测试

开发环境用 Python 3.13、`pysoem`、`pyserial`；本机 `zpin` 环境可用。Npcap 已安装并运行，但此电脑没有接入三路实机。避免用户站点包干扰时在 PowerShell 中运行：

```powershell
$env:PYTHONNOUSERSITE = '1'
& 'D:\miniconda3\envs\zpin\python.exe' -B master/master.py --smoke-test
& 'D:\miniconda3\envs\zpin\python.exe' -B -m unittest discover -s tests -v
```

`--smoke-test` 完整执行参考作业，不枚举或打开任何网卡/串口。`--smoke-test --inject-failure` 验证首次下行故障的收尾和非零退出码。自定离线作业可运行：

```powershell
& 'D:\miniconda3\envs\zpin\python.exe' -B master/master.py --simulate --angle -30 --length 20 --spacing 2 --depth 3
```

实机入口为 `master/master.py --live --config master/config.toml --confirm-datum`。模板刻意缺少实测数据；配置不完整时，程序在连接设备之前报错。程序连接 GX28 时会查询 `ZPIN_HEAD_PROTOCOL=2`，旧固件无法通过启动检查；必须先烧录并核对本仓库固件。**断电重启后的软件 0 不代表机械零位。** 每次实机启动先确认 CNC 工作零点与安全扫描 Z，再进入**编号式安全设置菜单**：`[1]` 使能伺服；`[2]` 点动伺服，先选方向（靠紧 / 张开）再输距离，单次不超过 0.5 mm；确认五工位已靠紧到机械基准后 `[3]` 伺服设零；确认 GX28 已位于安全待机点后 `[4]` 滑台设零；最后 `[5]` 开始植入。缺少任一零点确认时总控拒绝自动动作。运行时输入 `!` 请求停止；停机或释放电机后须重新确认零位。实机接入前还须核对串口/有线网卡、可用工作窗口、阀门释放规则和材料/丝材准备流程。不能以离线测试代替实机试运行。

实机 `[job]` 配置提供默认的架角、排长、点距和深度；命令行只覆盖明确传入的项目，例如 `--live --config master/config.toml --confirm-datum --angle 15 --length 20 --spacing 2 --depth 2 --datum-x 0 --datum-z -5`。程序在连接设备前校验最终参数、五针排程、CNC 软限位，以及**排间安全高度是否高过排内最高工作点**；对刀点 `(x0, z0)` 只能来自真机对刀，非交互路径必须用 `--datum-x/--datum-z` 显式给出（缺一个就报错退出）。`--rows N` 表示跑 N 排后正常收工；不给就一直跑到操作员叫停。离线 smoke/simulate 在未传参数时用 θ=+15°、排长 20、点距 2、深度 2 这套参考作业。

## 交互式向导（操作员入口）

`master/master.py --live` 不带 `--confirm-datum` 时进入向导，这是交给操作员的入口。带上 `--confirm-datum` 则走上面的非交互路径，行为不变。全程为中文提示，输入 `Q`（或 `QUIT`/`取消`）在任意一步中止；中止发生在连接设备之前时不会碰硬件。

向导依次采集两类信息，**分界线是"要不要每次重填"**：

| 类别 | 内容 | 落盘位置 |
|---|---|---|
| 环境 | EtherCAT 有线网卡、CNC 三维模组串口、GX28 滑台串口、CNC X/Y/Z 软限位 | `master/config.local.toml`，下次作为默认值 |
| 作业 | 架角 θ、一排的强化区长度、点间距、植入深度 | 不落盘，每次作业重新询问 |

环境配置写在模板**旁边**的 `master/config.local.toml`，叠加在 `master/config.toml` 之上，本文件里的键优先。模板本身不改动；本地文件不存在时行为与只用模板完全一致。该文件含本机串口与网卡信息，已在 `.gitignore` 中，不要提交。

几个刻意的设计：

- **网卡存人类可读描述**（如 `Realtek PCIe GbE Family Controller`），不是 pysoem 的 `\Device\NPF_{GUID}`——后者没人能手工输入。描述只在真实硬件分支里解析成 pysoem 名称，匹配不到或匹配到多块同型号网卡时在连接前报错。
- **串口列表优先显示 USB 串口**，蓝牙/虚拟口默认折叠但可用 `A` 展开（有人用 USB 网卡转 EtherCAT，过滤可能误伤），展开时会显示每一项被折叠的原因。CNC 与滑台的口不允许选同一个。
- **植入深度不超过 3 mm**，超出时给机械原因（碳管壁只有 2 mm，再往下就是金属接头）并重问。
- **作业参数立刻回显排程结果**（植入点数、五针动作次数、针距、伺服目标、**扎针覆盖长度与末端不扎针的余量**、滑台行程 `depth/cosθ`、针长等差步长 `p·tanθ`、排内 Z 变化），输入不合法时当场重问，而不是留到连接设备后报错。角度回显带符号，因为 `+15°` 和 `−15°` 是两套不同的针组。末端余量必须说出来：不说的话操作员要么以为整段都扎满了，要么得自己做一遍除法才发现少了零点几毫米。

采集完成后依次：连接三路 → 开启确认（伺服无逻辑零点或滑台未确认待机零点时转入**编号式安全设置菜单**：`[1]` 使能 / `[2]` 点动 / `[3]` 伺服设零 / `[4]` 滑台设零 / `[5]` 开始植入）→ **对刀两步**（都**不用操作程序**：第一步把 X 移到排头、Z 降到针尖刚好接触管顶母线，回车后程序读回 `(x0, z0)` 两个坐标；第二步把 Z 抬到够把管子转过一个周向位置的高度，回车后程序读回 `scan_z_mm`，**低于排内最高工作点会被当场拒绝并指出是哪一端最高**）→ 确认三项实机前提 → 打印最终生效参数 → 开跑。每个落点退回且 B 阀排气后，需剪丝并输入确认码才移动到下一落点；一排跑完后滑台自动抬到安全高度、回到排头，剪丝转管后输入确认码再跑下一排，不想再跑就输入 `DONE`（正常收工，不是急停）；运行中输入 `!` 请求三路停止。

运行结果逐落点写入 CSV、结束时写 JSON 摘要，默认目录为配置文件同级的 `runs/`（可用 `--results-dir` 改）。**中止也落盘**：跑了 37 个落点后急停，CSV 里就有 37 行、摘要里 `state=STOPPED`——这是事后查"跑到哪了"的唯一依据。CSV 带 BOM，便于在中文 Windows 的 Excel 里直接打开。

## 当前待核对的硬件事实

- 昨天成功执行“先下、后上”时，ESP32 烧录的 `.ino` 版本、执行前 `s` 位置、是否执行过 `z`。仓库新版固件已改为有符号窗口和启动对零门槛，但尚未用 Arduino 工具链编译/烧录，也未实机验证；本机的 C++ 桩测试不能替代这些步骤。
- 1–3 mm 植入深度对应的针尖与管面间隙、实际植入深度/露出长度、GX28 丝杆导程和细分、可重复的手动基准。
- 上阀 B 退针后是否释放，以及下一落点如何供丝/切丝。当前离线样例按仓库旧流程在退针后关闭 B；真实运行要求明确确认。
- TTC450 Pro 实际 X/Y/Z 工作限位、哪个针头定义 X=0。针距在 10–20 mm 之间，而强化区只有 ~20 mm，所以**每次五针里总有针落在强化区外**——按设计它们落在更长的管料上、事后切掉，程序不再把这种外伸当错误。管料到底够不够长、外伸针会不会挂到夹具，**由操作员上料时自己判断**（本次没有做料长闸门）。
- 排间安全高度取多少、以及手动转管的定位重复性，都还没有实机数据。

## 启动菜单与调试输出

在终端里**不带任何模式参数**运行 `master/master.py` 会进编号菜单：实机运行 / 仿真 /
自检 / 调试输出开关 / 退出。全程用编号选择，只有在必须读数值（作业尺寸、点动距离）
时才要求输入。菜单是**新增入口**，`--smoke-test` / `--simulate` / `--live` 三个参数
原样保留且互斥，脚本化调用继续走参数。非终端环境里不带模式参数运行会直接报用法
错误，不会挂住等输入。

`--debug`（菜单里是 `[4] 调试输出`）打开后，设备自己说的每一行都原样打到终端，
出错时**固件原话先出现、主控的转述随后**，且转述里带原文：

```
[GX28] > -5.000
[GX28] < 移动到 -5.00 mm (16000 步)...
[GX28] < 到达目标
[CNC ] < ok
[伺服] < 状态字=0x0237 到位
```

CNC 每秒 10 次的 `?` 状态轮询按状态变化折叠（心跳不是设备主动说的话）。关闭调试
**不等于少看东西**：设备报的错一个字不少地传上去，只是不再回显正常回话。

不想接硬件就想看这两样长什么样，跑 `python -B scripts/demo_no_hardware.py`：
它跑的是生产代码本身，只把串口和伺服对象换成假的。
